# 综合态势与多源感知-AI智能研判子系统设计方案

## 一、项目概述

### 1.1 系统背景

综合态势与多源感知系统是面向海上态势感知与管控的综合管理平台，接入雷达、AIS、北斗、光电视频、频谱侦测、气象水文等多源异构数据，支撑目标管控、预警事件、设备联动、AI研判、数据分析等业务场景。

AI智能研判子系统是平台的"分析大脑"层，在既有预警事件与设备联动能力之上，将多源数据、规则告警、设备资源整合为可解释的AI研判结论与处置建议，并为值班人员提供自然语言交互入口。

### 1.2 子系统定位

- 算法中台：统一管理目标识别、行为分析、风险评估、事件推荐等AI算法服务的运行状态、版本、数据源与授权设备，对识别与研判结果提供人工复核闭环。
- AI助手：通过自然语言多轮交互查询目标、告警、区域等信息，辅助值班人员快速理解系统状态并生成研判结论与处置建议。
- 多源融合智能体（MIFA）：按"感知-融合-推理-联动"四层架构闭环运转，发现单源数据难以发现的异常，并自动调度设备完成核验与处置。

### 1.3 实施方式

本版本按前端原型 + 模拟AI引擎（Mock）实现：算法服务状态、识别结果、聊天响应、智能体流水线均由 Mock 引擎模拟，页面交互、数据流向与权限控制按真实系统设计；后续接入真实算法与大模型服务时，仅替换 API 层，页面结构保持不变。

### 1.4 核心价值

- 将多屏人工比对升级为可解释的AI结论，缩短研判时间
- "规则兜底 + AI增强"双通道，降低误报与漏报
- 自然语言查询降低新用户上手成本
- 智能体自动联动光电/无人机核验，缩短应急响应链路

## 二、功能范围

### 2.1 菜单结构

```
AI智能研判（一级菜单）
├── 算法中台       /ai/algorithm   （Tabs：算法服务 / 船型识别 / 行为分析）
├── AI助手         /ai/assistant
└── 多源融合智能体 /ai/mifa
```

### 2.2 功能模块总览

| 模块 | 功能点 | 说明 |
|------|--------|------|
| 算法中台 | 算法服务管理 | 算法服务运行状态、版本、数据源、授权设备管理，支持重启、版本切换与异常告警 |
| | 船型识别 | 基于光电视频的多类型船舶AI识别，低置信度自动进入人工复核 |
| | 行为分析 | 作业模式识别、异常绕行、频繁变向、接近重点目标，输出分级告警与研判依据 |
| AI助手 | 自然语言交互 | 多轮对话查询目标、告警、区域信息，结果以地图、列表、图表呈现 |

## 三、核心模块设计

### 3.1 算法中台

**路由**：`/ai/algorithm`

**页面布局**：顶部统计卡片 + Tabs（算法服务 / 船型识别 / 行为分析）

#### 3.1.1 算法服务管理

**统计卡片**：算法服务总数、运行中、异常、今日调用量；异常数量大于 0 时高亮提示。

**算法服务表格**：

| 列名 | 类型 | 说明 |
|------|------|------|
| 服务名称 | 文本 | 船型识别/行为分析/风险评估/事件推荐 |
| 服务类型 | 标签 | 目标识别/行为分析/风险评估/事件推荐 |
| 运行状态 | 标签 | 运行（绿）/异常（红）/停止（灰）/升级中（蓝） |
| 当前版本 | 文本 | 如 v2.3 |
| 数据源 | 多选摘要 | 雷达/AIS/北斗/光电/轨迹/事件 |
| 授权设备 | 数字 | 已授权光电/雷达/无人机设备数 |
| 今日调用量 | 数字 | 实时刷新 |
| 平均延迟 | 文本 | 毫秒 |
| 准确率 | 百分比 | 带趋势 |
| 最近更新时间 | 日期时间 | - |
| 操作 | 按钮 | 详情/重启/版本切换 |

**操作说明**：

- 详情：展示服务配置、数据源明细、授权设备列表、近期调用趋势
- 重启：模拟服务重启倒计时，重启期间状态为"升级中"，完成后恢复"运行"
- 版本切换：选择目标版本，确认后切换，记录切换时间与操作人
- 异常：状态为异常时行内红点提示，支持一键查看异常详情

**Mock 模拟规则**：

- 心跳模拟：算法服务按周期更新调用量、延迟、准确率；小概率随机进入"异常"状态
- 异常自动告警：与现有告警消息风格一致，异常恢复后提示"服务已恢复"
- 支持"重置演示数据"，一键恢复初始算法服务数据

#### 3.1.2 船型识别

**页面布局**：左侧识别画面与目标列表 + 右侧识别结果列表

**识别画面**：

- Canvas 模拟光电画面 + 识别框，展示船型标签与置信度
- 支持切换光电设备，识别画面与设备联动页面选中设备同步

**识别结果列表**：

| 列名 | 类型 | 说明 |
|------|------|------|
| 识别时间 | 日期时间 | - |
| 目标名称 | 文本 | 目标名称 + MMSI |
| 来源设备 | 文本 | 光电设备名称 |
| 识别船型 | 标签 | 渔船/货船/客船/快艇/橡皮艇/三无船 |
| 置信度 | 百分比 | 低置信度标红 |
| 复核状态 | 标签 | 自动通过/待人工复核 |
| 操作 | 按钮 | 复核/查看快照 |

**人工复核**：

- 置信度 >= 80%：自动通过
- 置信度 < 80%：进入"待人工复核"，操作列提供"复核"入口
- 复核抽屉展示画面快照、识别类型、置信度、来源设备；支持确认或修改船型
- 复核通过后自动给目标打船型标签，可勾选"同时生成告警"
- 复核记录写入操作日志，记录复核人、复核时间、原识别结果与最终结果

#### 3.1.3 行为分析

**规则配置卡**（按算法类型分组）：

| 算法类型 | 配置项 |
|----------|--------|
| 作业模式识别 | 捕捞作业/运输航行/游弋停泊模式识别开关 |
| 异常绕行 | 绕行角度阈值、持续时长、告警级别 |
| 频繁变向 | 变向次数阈值、统计时长、告警级别 |
| 接近重点目标 | 最近距离阈值、持续时长、告警级别 |

**分析结果列表**：

| 列名 | 类型 | 说明 |
|------|------|------|
| 分析时间 | 日期时间 | - |
| 目标名称 | 文本 | 目标名称 + MMSI |
| 作业模式 | 标签 | 捕捞作业/运输航行/游弋停泊 |
| 异常类型 | 标签 | 异常绕行/频繁变向/接近重点目标 |
| 严重程度 | 标签 | 提示/一般/重要/紧急 |
| 置信度 | 百分比 | - |
| 研判依据 | 文本 | 展开查看证据链 |
| 关联事件 | 文本 | 事件编号或"-" |
| 操作 | 按钮 | 生成告警/关联已有事件/查看证据链 |

**操作说明**：

- 生成告警：写入事件闭环管理，事件来源标记为"AI分析"
- 关联已有事件：按目标 + 时间窗匹配规则事件，合并为"规则+AI复合"，AI结论回填事件详情
- 查看证据链：展示参与分析的数据源、时间点、特征值与推理步骤

### 3.2 AI助手

**路由**：`/ai/assistant`

**页面布局**：左侧对话区 + 右侧结果区

#### 3.2.1 自然语言交互

- 消息流：用户消息 + 模拟AI回复（打字机效果），支持推荐问题快捷点击
- 意图识别：目标查询/告警查询/区域查询/操作指引/辅助研判
- 结果渲染：目标按地图点位或列表展示；告警按等级图表与列表展示；区域按地图高亮展示；操作指引按步骤卡片展示
- 权限裁剪：根据当前用户角色过滤可访问数据，越权数据不返回

**示例意图与响应**：

| 用户问题 | 意图 | 响应 |
|----------|------|------|
| 显示附近的渔船 | 目标查询 | 地图点位 + 目标列表 |
| 今天的紧急告警有哪些 | 告警查询 | 告警列表 + 等级分布图表 |
| 禁航区在哪 | 区域查询 | 地图高亮区域 |
| 怎么调用光电联动 | 操作指引 | 步骤卡片 + 快捷跳转 |
| 分析这个目标的风险 | 辅助研判 | 研判结论 + 处置建议 |

#### 3.2.2 辅助研判

**入口**：目标/告警详情按钮，或对话中直接询问

**研判结论抽屉**：

- 事件摘要、AI结论、置信度
- 数据来源列表：每条来源可展开查看原始数据
- 处置建议：按优先级排序，展示建议动作、预期效果、所需资源
- 快捷操作：联动核验/派发事件/生成事件/反馈

**反馈**：

- 类型：误报/漏报
- 原因：天气干扰/算法误判/参数不当/其他
- 样本说明：文本，不超过 200 字
- 提交后进入反馈记录，供算法版本优化统计

### 3.3 多源融合智能体

**路由**：`/ai/mifa`

**页面布局**：左侧四层流水线 + 中间地图/融合视图 + 右侧运行日志

#### 3.3.1 四层闭环

**感知层**：展示雷达、AIS、北斗、光电、频谱、气象等数据源接入状态、实时数据量、时空对齐成功率；异常数据源高亮提示。

**融合层**：展示目标匹配与身份确认过程，融合目标表格字段：目标名称、数据源组合、融合置信度、状态（已确认/待确认/已分离）。

**推理层**：交叉识别单源数据难以发现的异常，每条推理结果展示异常类型、置信度、证据链与影响范围。

**联动层**：根据推理结果自动生成联动动作，展示动作类型（调用光电/调度无人机）、目标设备、状态与执行结果；执行记录关联设备联动取证记录。

#### 3.3.2 运行控制

- 启动/暂停：控制流水线推进，暂停后各层数据保持当前状态
- 自动联动开关：关闭后推理结果只生成建议，不自动执行联动
- 参数配置：时间窗、置信度阈值、联动设备偏好
- 历史记录：按运行批次查看融合目标、推理结果、联动动作与日志

#### 3.3.3 模拟引擎

- 定时器驱动流水线各层数据变化，周期性生成融合目标、推理结果与联动动作
- 联动动作复用 deviceStore，跳转光电/无人机页面并携带事件与目标上下文
- 页面销毁时统一清理定时器，避免内存泄漏

### 3.4 与行为预警的关系

采用"规则兜底 + AI增强"双通道，与预警规则管理中的行为预警互补协同：

- 行为预警继续负责航速异常、航向异常、异常停留、轨迹断线等显式规则检测
- AI行为分析负责作业模式、异常绕行、频繁变向、接近重点目标等复杂模式检测
- 同目标、同行为类型、同一时间窗内事件去重，主事件来源标记为"规则命中 / AI分析 / 规则+AI复合"
- AI对规则事件回填研判结论（如轨迹断线分类），反馈结果进入误报治理，并可给出规则参数调整建议
- 两者命中后均进入事件闭环管理，复用现有状态流转、派发处置与归档能力

### 4.2 数据流向

```
多源数据/预警事件/设备状态
        │
        ▼
算法中台（服务管理/船型识别/行为分析）
        │
        ▼
识别与行为分析结果 ──去重与来源标记──→ 事件闭环管理
        │
        ▼
AI助手（自然语言查询 / 辅助研判 / 反馈）
        │
        ▼
多源融合智能体（感知 → 融合 → 推理 → 联动）
        │
        ▼
deviceStore ──→ 光电/无人机联动与取证记录
```

### 4.3 关键数据关系

- 算法服务 1:N 识别结果、行为分析
- 目标 1:N 识别结果、行为分析、融合目标
- 告警事件 1:0..1 处置建议；1:N 反馈记录
- MIFA运行批次 1:N 融合目标、推理结果、联动动作
- 联动动作与设备联动取证记录通过 eventId、deviceId 关联

## 五、边界情况处理

### 5.1 算法服务异常

- 算法离线/异常：页面提示、相关操作禁用、历史结果缓存保留
- 重启中：结果列表暂停刷新，重启完成后自动恢复
- 版本切换失败：自动回退旧版本并提示切换失败原因

### 5.2 识别与研判边界

- 低置信度结果必须人工复核后才能生成告警
- 无识别目标时显示空态，不产生空结果记录
- 行为分析无命中时不产生告警，仅保留分析轨迹日志
- 复核修改船型后，历史识别记录保留原始结果与修改结果，可追溯

### 5.3 AI助手边界

- 意图未命中：给出推荐问题回退，不展示空结果
- 越权查询：不返回数据，提示可查询的权限范围
- 多轮上下文丢失：提示用户重新表述问题
- 查询结果为空：展示"暂无数据"与扩大筛选条件建议

### 5.4 智能体边界

- 暂停时流水线停止推进，已生成数据与日志保留
- 联动失败：记录失败原因，状态标记为 failed，允许人工接管
- 目标无关联在线设备：提示并允许手动选择其他设备
- 自动联动开关关闭时，推理结果只生成建议不执行动作

### 5.5 事件去重边界

- 同一目标 + 行为类型 + 时间窗内，规则与AI重复命中只保留一条主事件
- 主事件来源按触发时序与置信度确定，次要命中结果作为研判依据合并
- 人工确认结果与AI自动生成结果冲突时，以人工确认为准

### 5.6 权限边界

- 指挥员：全部权限
- 值班员：查看、复核、反馈、提交处置建议
- 设备操作员：执行智能体联动动作
- 运维管理员：管理算法服务与版本，不操作业务
- 无权限按钮直接隐藏，不展示不可点击状态

### 5.7 空态与演示边界

- 所有列表、图表、流水线提供空态文案
- Mock 数据支持"重置演示数据"，一键恢复初始状态
- 模拟定时器在页面销毁时统一清理，避免内存泄漏
- 演示数据重置后，反馈记录与运行日志一并恢复初始状态
