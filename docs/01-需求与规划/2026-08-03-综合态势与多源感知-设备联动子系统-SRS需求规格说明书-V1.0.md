# 二、项目概述

## 2.1 项目背景

随着海上态势感知和预警处置业务的深化，预警事件产生后的现场核验与处置环节面临以下挑战：

1. **现场核验手段割裂**：光电、无人机、雷达等设备分散在多个独立系统中，值班员需切换多个画面才能确认现场，响应时间长，容易错过最佳处置时机。
2. **设备资源状态不透明**：光电、无人机、雷达、气象站等设备是否在线、是否可用、安装在哪里缺乏统一展示，联动时无法快速判断可用资源。
3. **取证留痕依赖人工**：截图、录像、喊话等处置动作缺少统一记录，难以与预警事件关联，事后复盘和执法取证不完整。
4. **多源协同研判不足**：光电视频、无人机空中视角、雷达回波等数据未形成协同链路，单手段核验容易漏判、误判，研判准确率有限。
5. **任务调度缺少统一编排**：无人机航线规划、任务下发、异常返航等过程分散，缺少可视化的任务编排和执行记录，安全风险难以管控。

为解决上述问题，建设设备联动子系统，以预警事件为入口、以设备操作为执行手段，实现"告警发现 → 现场核验 → 取证处置"的闭环联动，提升海上态势管控和应急处置能力。

## 2.2 项目建设目标

本项目旨在建设设备联动子系统，实现以下目标：

1. **建立统一的设备状态总览**：按类型、区域分组展示雷达、光电、无人机、气象站等设备，实时呈现在线、离线、故障状态和设备分布，支持一键打开对应设备的联动控制页面。
2. **实现光电远程核验与取证**：提供可见光/红外实时视频查看、云台控制、预置位与巡航、截图录像、预设喊话等功能，支撑值班员远程确认现场并留存证据。
3. **实现无人机快速响应与任务调度**：在线监控无人机位置、电量与续航，支持航线规划、续航校验、任务下发与执行进度跟踪，低电量或失联时自动返航。
4. **实现雷达回波辅助研判**：通过 PPI 回波、目标列表、量程增益调节和回波高亮联动，辅助值班员对重点目标进行多手段交叉确认。
5. **实现全流程联动留痕**：截图、录像、喊话、航线任务等操作统一记录，可关联预警事件和目标，供事件详情查询与事后审计。

## 2.3 项目建设范围

本项目建设范围包括：

**系统端**：
- PC端管理后台（Web应用）

**功能模块**：
- 设备总览：设备树分组、状态统计、地图点位、设备详情、快速打开控制窗口
- 光电联动：实时视频查看、云台控制、预置位与巡航、截图录像、喊话、取证记录
- 无人机联动：状态监控、航线规划、航线模板、任务调度、任务与异常记录
- 雷达监测：PPI回波展示、运行参数与参数调节、目标列表、雷达取证
- 预警事件联动入口：事件列表发起联动视频、事件上下文传递、取证记录关联事件

**数据范围**：
- 设备基础数据（名称、编号、类型、型号、所属区域、安装位置、接入协议）
- 设备运行状态数据（在线状态、信号强度、最近心跳、运行参数）
- 光电联动数据（云台角度、倍率、预置位、巡航计划）
- 无人机数据（实时位置、电量、航线模板、任务执行记录）
- 雷达数据（雷达站参数、目标回波数据）
- 取证与操作记录（截图、录像、喊话、任务记录及事件关联）

**不包含的功能**：
- 设备档案的完整维护与全生命周期管理（本子系统仅查看，数据来源于设备档案模块）
- 真实光电/无人机/雷达厂商协议接入（本阶段为演示环境模拟数据，后续迭代接入真实设备）
- 移动端H5/App（后续迭代实现）
- 预警规则判定和事件闭环流程（由预警事件子系统提供）

| 软限位 | 系统设定的云台可转角度范围，超出后停止转动并提示 |
| 联动上下文 | 从预警事件进入联动页面时携带的事件编号、目标、设备等信息 |

# 三、项目建设内容

## 3.1 总体功能架构

设备联动子系统作为综合态势与多源感知系统的一级菜单模块，包含以下功能结构：

**PC 端（管理后台）**

- 设备联动（一级菜单）
  - 设备总览（二级菜单）
  - 光电联动（二级菜单）
  - 无人机联动（二级菜单）
  - 雷达监测（二级菜单）

预警事件子系统的"事件闭环管理"中提供"联动视频"入口，携带事件、目标、设备上下文进入本子系统的光电联动页面，具体见 3.5.5。

### 系统技术架构

设备联动子系统构建于综合态势与多源感知系统的整体技术架构之上，前端采用组件化单页应用，设备状态与联动操作通过统一的数据服务与演示数据对接，后续可平滑替换为真实设备接入。
