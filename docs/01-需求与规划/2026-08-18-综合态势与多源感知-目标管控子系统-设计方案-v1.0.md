# 综合态势与多源感知-目标管控子系统设计方案

## 一、项目概述

### 1.1 系统背景

综合态势与多源感知系统是面向海上态势感知与管控的综合管理平台，接入雷达、AIS、北斗、光电视频、频谱侦测、气象水文等多源异构数据，支撑目标管控、预警事件、设备联动、AI研判、数据分析等业务场景。

目标管控子系统定位为平台的目标数据中心与人工研判入口，面向值班人员提供融合目标查询、单目标研判、重点关注与标签管理等能力，并与预警事件、设备联动、AI智能研判子系统形成闭环。

### 1.2 子系统定位

- 目标总览：融合目标统一查询与筛选入口，快速定位重点关注、高风险与待人工确认目标。
- 单目标研判：集中展示目标属性、动态信息、风险等级、融合置信度、历史轨迹与报警历史，支撑单目标深度研判。
- 目标标注：维护重点关注目标列表与自定义标签体系，沉淀人工研判信息并支持多人协作。

### 1.3 实施方式

本版本按前端原型 + Mock 数据实现。以生产 Kafka 融合目标字段契约为数据底座，从真实融合目标快照中精选 15 条数据，再补齐原型所需的船名、船型、风险等级、融合置信度、轨迹与报警历史等业务字段；页面交互、数据流向与权限控制按真实系统设计，后续接入真实后端时仅替换 API 层。

### 1.4 核心价值

- 将分散在事件、设备、AI模块中的目标信息汇总为统一目标视图，缩短查找与研判时间。
- 以五级风险、判定依据和融合置信度让目标状态可解释、可追溯。
- 通过关注与标签体系沉淀值班人员的判断经验，形成多人协作的研判档案。

## 三、核心模块设计

### 3.1 目标总览

**路由**：`/target/overview`

**页面布局**：顶部统计卡片 + 筛选栏 + 目标列表，不使用地图。

**统计卡片**：目标总数、重点关注、待人工确认、高风险；数量大于 0 时对应卡片高亮。

**筛选栏**：

| 筛选项 | 说明 |
|--------|------|
| 关键字 | 按 MMSI / 目标编号 / Source ID 模糊查询 |
| 目标类型 | 正常船只、三无船只 |
| 数据来源 | 雷达、AIS、电子围栏、海兰信、厦漳泉 |
| 风险等级 | 低、较低、中、较高、高 |
| 时间范围 | 近1小时、近6小时、近24小时、自定义日期时间 |
| 区域范围 | 全部、厦门湾、漳州湾、泉州湾 |

不做输入联想与搜索历史，保持轻量查询。

**目标列表**：

| 列名 | 说明 |
|------|------|
| 目标名称 | 船名或无 MMSI 雷达目标编号 |
| MMSI / 显示编号 | MMSI 合法时展示 MMSI，否则展示 fusion_id |
| 目标类型 | 正常船只 / 三无船只（含未确认、已确认） |
| 数据来源 | 融合类型与来源组合 |
| 风险等级 | 五级标签 |
| 融合置信度 | 百分比，低置信度标红 |
| 状态 | 正常 / 重点关注 / 待人工确认 |
| 航速 | 节 |
| 航向 | 度 |
| 更新时间 | 北京时间 |
| 距离 | 相对厦门湾监控中心的距离，可排序 |
| 操作 | 关注 / 备注 / 查看详情 |

- 支持按时间、距离、速度、风险等级点击表头升降序排序。
- 点行进入单目标研判详情。
- 行内快捷关注与备注，与目标标注模块数据联动。
- 导出按钮将当前筛选结果直接导出为 Excel/CSV，不做导出字段勾选。

### 3.2 单目标研判详情

**路由**：`/target/detail/:fusionId`（隐藏路由，从目标总览或目标标注进入）

**页面布局**：顶部目标身份条 + 右侧 Tabs，不设大尺寸地图。

**身份条**：目标名称、MMSI/显示编号、船型、风险等级、融合标识、三无状态、关注状态，以及返回、关注、备注、联动视频入口。

**Tab 实时研判**：

- 基础属性区域：船名、MMSI、船型、尺寸、国籍，内嵌一块静态小地图示意图展示目标当前位置，不做真实地图。
- 动态信息：实时位置、航向、航速、转向率、更新时间。
- 风险模块：五级风险色带、判定依据列表、风险等级变更历史时间线。
- 多源融合：融合来源徽标（雷达/AIS/北斗/光电/电子围栏）、融合置信度百分比、来源明细展开、低置信度“待人工确认”及确认操作。

**Tab 历史轨迹**：

- 左侧静态轨迹示意图：示意底图 + 轨迹折线 + 事件点标记，不接入真实地图。
- 查询区：支持任意时间段历史轨迹查询。
- 播放控制：播放/暂停、1x/2x/4x/8x/16x 倍速、逐帧进退、进度条拖动。
- 事件点：告警等关键事件自动标记，点击定位。
- 导出：轨迹 KML 与 CSV 双格式导出。
- 截图取证：原型阶段生成带时间水印的模拟取证记录。

**Tab 关联信息（报警历史）**：

- 展示该目标历史告警：告警类型、告警级别、触发时间、处置状态、处置结果。
- 支持按告警类型、级别、时间范围、处置状态筛选。
- 点击告警可查看详情。
- 关联视频查询本轮不做，后续版本补充。

### 3.3 目标标注

**路由**：`/target/marking`

**页面布局**：Tabs（重点关注 / 标签管理）。

**重点关注**：

- 统计卡：关注总数、高风险关注、今日新增关注。
- 关注目标列表：按风险等级、标签、添加时间筛选。
- 支持批量添加/取消关注，列表导出。
- 点击目标进入单目标研判详情。

**标签管理**：

- 自定义标签增删改，支持标签颜色配置。
- 按标签筛选目标并统计各标签数量。
- 备注与标签变更历史时间线：记录操作人、操作时间、变更内容。
- 支持多人协作补充研判信息。

### 3.4 Mock 数据设计

- 从 585 条真实融合目标中精选 15 条，覆盖 `ais`、`radar`、`frame_code`、`radar+ais`，以及有/无 MMSI、三无未确认/已确认等形态。
- 原始字段保留 Kafka 契约结构：`fusion_id`、`display_id`、`mmsi`、`source_id`、经纬度、航向、航速、`event_time`、`fusion_type`、`three_no_status`、`sources`。
- 原型补齐字段：船名、呼号、船型、国籍、尺寸、吨位、风险等级、风险判定依据、融合置信度、风险变更历史、24 小时轨迹、报警历史。
- 关注、标签、备注、风险确认、筛选与布局状态由 Pinia 管理并持久化到 localStorage，支持一键重置演示数据。

## 四、数据结构与流向

### 4.1 目标数据结构

以 Kafka 融合目标字段契约为底座，原型阶段补齐业务字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| fusion_id | string | 融合目标稳定技术标识 |
| display_id | string | 页面展示编号，优先 MMSI，否则使用 fusion_id |
| mmsi | string/null | 合法 MMSI，无则 null |
| source_id | string | 电子围栏来源编号，可为空 |
| longitude / latitude | number | WGS-84 坐标 |
| heading | number | 航向，0~360 度 |
| speed | number | 航速，节 |
| event_time | string | 目标测量时间，北京时间 |
| fusion_type | string | radar / ais / frame_code / radar+ais 等 |
| three_no_status | string | 空 / unverified / confirmed |
| sources | object | ais / xzq / hailanxin / fence 等来源明细 |
| ship_name | string | 原型补齐：船名 |
| call_sign | string | 原型补齐：呼号 |
| vessel_type | string | 原型补齐：船型 |
| nationality | string | 原型补齐：国籍 |
| length / breadth / tonnage | number | 原型补齐：尺寸与吨位 |
| risk_level | number | 1~5，低到高 |
| risk_reasons | string[] | 风险判定依据 |
| fusion_confidence | number | 融合置信度百分比 |
| confirm_status | string | confirmed / pending，低置信度待人工确认 |
| is_followed | boolean | 是否重点关注 |
| tags | string[] | 自定义标签 |
| notes | string[] | 人工备注 |
| risk_history | object[] | 风险等级变更历史 |
| trajectory | object[] | 历史轨迹点，含时间与事件标记 |
| alert_history | object[] | 目标历史告警 |

### 4.2 API 设计

| 接口 | 方法 | 说明 |
|------|------|------|
| /admin/target/list | GET | 目标列表，支持筛选、排序、分页 |
| /admin/target/detail/:fusionId | GET | 目标详情 |
| /admin/target/trajectory/:fusionId | GET | 历史轨迹 |
| /admin/target/alert-history/:fusionId | GET | 目标报警历史 |
| /admin/target/attention | PUT | 批量关注/取消关注 |
| /admin/target/note | PUT | 新增备注 |
| /admin/target/tags | PUT | 更新标签 |
| /admin/target/confirm | PUT | 风险等级确认 |
| /admin/target/tags/stats | GET | 标签数量统计 |
| /admin/target/reset | POST | 重置演示数据 |

### 4.3 数据流向

- 原始 15 条融合数据存放于 `src/mock/json/fusionTargets.json`。
- `src/mock/target.ts` 将原始数据转换为完整目标模型，并生成轨迹、风险、置信度、报警历史等原型数据。
- `src/api/target.ts` 提供列表、详情、轨迹、报警历史、关注、备注、标签、风险确认、重置等接口。
- `src/store/modules/target.ts` 管理关注、标签、备注、风险确认与演示数据状态，localStorage 持久化。
- 目标总览与目标标注共享同一份目标状态；进入单目标研判详情后按 fusion_id 读取详情数据。
- 目标总览列表点击关注、备注，或目标标注模块变更关注与标签时，通过 Pinia 同步更新并写入变更历史。

## 五、边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 无 MMSI 目标 | MMSI 显示 `--`，展示编号使用 fusion_id，风险权重上调 |
| 三无未确认 / 已确认 | 列表与筛选按目标类型区分，详情展示三无状态与判定依据 |
| 低置信度目标 | 强制“待人工确认”，确认后写入风险变更历史并恢复为已确认 |
| 静止目标 | 轨迹退化为单点并提示“目标未移动”，播放控件禁用 |
| 无轨迹数据 | 轨迹 Tab 显示空状态，导出按钮禁用 |
| 无报警历史 | 报警历史显示空状态，不渲染空表格 |
| 筛选无结果 | 空状态展示，提供一键重置筛选 |
| 关注/标签变更 | 记录操作人、操作时间与变更内容，可追溯 |
| 演示数据重置 | 一键恢复初始 15 条目标及关注、标签、备注、风险确认默认状态 |
