# 模块依赖关系描述规范

> 供 req-analyzer agent 使用。分析功能模块时，必须识别并输出模块间的依赖关系。

---

## 依赖关系的三种类型

### 类型一：数据来源依赖

本模块的某个字段，数据来源于另一个模块。

**识别方式：** 表单中有"选择"类字段（下拉、层级选择、多选），其选项来自其他模块的数据。

**输出格式：**
```
[本模块].[字段名] 来源于 [依赖模块]
  - 依赖条件：[依赖模块]中[状态/条件]的数据
  - 影响：[依赖模块]无数据时，本模块该字段无可选项
```

**示例：**
```
商品.商品分类 来源于 分类管理
  - 依赖条件：分类管理中已启用的分类
  - 影响：分类数据为空时，新增商品时分类字段无可选项

商品.所属品牌 来源于 品牌管理
  - 依赖条件：品牌管理中已启用的品牌
  - 影响：无品牌数据时，所属品牌字段无可选项
```

---

### 类型二：状态联动影响

本模块的数据状态变更，影响其他模块的行为。

**识别方式：** 业务规则中有"停用后不可选"、"删除后影响"、"状态变更后"等描述。

**输出格式：**
```
[本模块].[状态变更] → 影响 [目标模块].[具体行为]
  - 触发条件：[状态从X变为Y]
  - 影响范围：[目标模块中哪些操作受影响]
  - 影响方式：[不可选/隐藏/自动更新等]
```

**示例：**
```
商品.商品状态=下架 → 影响 订单.商品选择
  - 触发条件：商品状态变更为"下架"
  - 影响范围：新建订单选择商品时，该下架商品
  - 影响方式：商品不可选

商品分类.状态=停用 → 影响 商品.商品分类字段
  - 触发条件：商品分类被停用
  - 影响范围：新增/编辑商品时的分类选择
  - 影响方式：停用的分类不出现在选项中
```

---

### 类型三：关联保护约束

本模块的数据被其他模块引用时，不能直接删除。

**识别方式：** 业务规则中有"删除前检查"、"有关联时阻止"、"先解除绑定"等描述。

**输出格式：**
```
[本模块] 被 [引用模块] 引用
  - 引用关系：[引用模块]的[字段名]引用了[本模块]的数据
  - 保护规则：[本模块]有被引用数据时，阻止删除
  - 提示文案：[原文]
```

**示例：**
```
商品分类 被 商品 引用
  - 引用关系：商品.商品分类 引用了 商品分类 的数据
  - 保护规则：该分类下有商品时，阻止删除分类
  - 提示文案：该分类下有 X 件商品，请先将商品调整至其他分类

角色 被 用户 引用
  - 引用关系：用户.所属角色 引用了 角色 的数据
  - 保护规则：角色被用户引用时，阻止删除角色
  - 提示文案：该角色已被用户引用，请先解除关联
```

---

## req-analyzer 输出格式

分析完一个功能模块后，在摘要末尾附上依赖关系：

```
## 模块依赖关系

### 数据来源依赖
- [字段名] ← [依赖模块]（[依赖条件]）
- [字段名] ← [依赖模块]（[依赖条件]）

### 状态联动影响
- [本模块状态变更] → [目标模块受影响行为]

### 关联保护约束
- 本模块被 [引用模块] 引用，有引用时阻止删除
- 本模块引用了 [被引用模块]，需先确认被引用模块有数据
```

## 初始化顺序推断

根据依赖关系，推断功能模块的初始化顺序（哪些模块需要先配置）：

```
基础数据层（无依赖）：
  商品分类、品牌管理、部门管理、角色管理

业务数据层（依赖基础数据）：
  商品（依赖：商品分类、品牌）
  用户（依赖：部门、角色）
  收货地址（依赖：用户）

业务流程层（依赖业务数据）：
  购物车（依赖：商品、用户）
  订单（依赖：商品、用户、收货地址）
  支付单（依赖：订单）
  售后工单（依赖：订单、用户）
```
